# gen_twins: executable twins of ACSL logic definitions

Plan §4 item 5 and §5 step 0: runtime checking with E-ACSL needs every
logic definition the annotations use to be executable.  E-ACSL 33 runs
predicates whose quantifiers are bounded over integers, but not
inductive predicates, binders over `\list` values or pointers,
`\base_addr`, or predicates under labels.  `gen_twins.py` takes the
spec block of an annotated C file and generates:

- a **C twin** for every inductive predicate (and for each predicate or
  logic function a twin calls), with a step bound;
- **witness functions** that compute the values of `\exists` / `\forall`
  variables over lists and pointers, derived from each inductive's
  cases;
- the **executable spec block**: each definition E-ACSL can run, in
  ACSL, with inductives replaced by their twins and list / pointer
  binders replaced by witnesses;
- a **manifest** (builtins, their C signatures, witness modes, dropped
  definitions) that `gen_rac.py` uses to translate the annotations of
  the code, and **diagnostics** naming every definition it did not
  translate, with the reason.

Test code only: nothing here enters a proof or the trust base.

```bash
# inside the M0 image (../env/run.sh), from the directory of the files:
python3 -I gen_twins.py SRC.c OUTDIR [--prefix rac] [--include TYPES.h] \
    [--cpp-args="-I..."]
tests/check.sh               # generality tests (lseg, tree, bst; refusals)
../bench/b1/rac/check.sh     # B1: twins + E-ACSL + the seven mutants
```

The first run builds the Frama-C plugin in `dump/` (`dune build`, a few
seconds).  Output in `OUTDIR` (with `--prefix P`):

| File | What |
|------|------|
| `P_twins.h` | prototypes of the builtins; no typedefs, so `gcc -include` works on E-ACSL's output |
| `P_twins.c` | the twins; compile with `rac_rt.c` and the types header |
| `P_spec.h` | the executable spec block (replaces the source's, by `gen_rac.py`) |
| `P_twins.json` | manifest: `builtins` (name → result and parameter kinds), `preds` (witness modes per predicate), `dropped` (name → reason), `spec_sha256` |
| `P_twins.txt` | diagnostics: one line per definition: twin / ACSL / left out / NOT TRANSLATED, and the witness modes |
| `P_logic.json` | Frama-C's typed AST of the logic declarations (from `dump/`) |

The generated files are build outputs (under `build/`, gitignored),
regenerated by every `check.sh` run (0.4 s for B1): checking them in
would need a staleness check, and the generator is deterministic.  To
read them: `../bench/b1/rac/build/twins/` after a B1 run.

## Why Frama-C's parser (`dump/`)

The generator reads the spec through a 200-line Frama-C plugin
(`dump/logic_dump.ml`, option `-logic-dump FILE.json`) that writes the
typed AST of every global logic declaration as JSON; it never parses
ACSL text.  The alternatives were a hand-written ACSL parser (as
`gen_rac.py` does, with regexes, for annotations) or Frama-C's
`-print` output (still text).  The AST gives, for free and exactly as
WP sees them: operator precedence (`a ==> b && c`), the types of every
variable and term (which binders are lists, which pointers, which
fields are pointers), labels, implicit coercions, `\Cons` / `\Nil` as
constructors, and name resolution.  The JSON keeps Frama-C's own
printing of every node (`pp`), used in diagnostics.  The generator
itself is Python (easier to change than an OCaml plugin, and it is
where the rules live).

## Input subset

Global logic declarations of SRC.c (the spec block; declarations from
included files are visible but not translated):

- `inductive P{L}(...) { case ...: \forall ...; p1 ==> ... ==> P(...); }`
  with at most one label; premises that are predicates over the current
  state;
- `predicate` / `logic` definitions with at most one label;
- terms: variables, `\null`, integer constants, `p->f`, `x.f`, `a[i]`,
  `&p->f`, arithmetic, casts, `?:`, `\nth`, `\length`, `\concat`,
  `\Cons`, `\Nil`, applications of definitions;
- predicates: `== != < <= > >=` (lists by value), `&& || ==> <==> ^^ !`,
  `\valid`, `\valid_read`, bounded integer `\forall` / `\exists`
  (`lo <= k < hi`), `\forall` / `\exists` over lists and pointers when
  a witness exists (below), and in ACSL output also `\initialized`,
  `\offset`, `\separated`, `\at`;
- the ghost liveness model of `ariadne_alloc.h`: `heap(b)`,
  `dead(v, b)`, and `heap(\base_addr(p))` / `dead(v, \base_addr(p))`,
  which become the allocation registry (`rac_heap`, `rac_dead`,
  `rac_heap_of`, `rac_dead_of`).

## Translation rules

### Inductive predicate → decision twin

`P(a0, ..., an)` becomes `int m_P(a0, ..., an, depth)`: the cases in
order, each a block that jumps to the next case when something fails;
true when a case gets to the end, false when none does.  For a case
`\forall xs; p1 ==> ... ==> pk ==> P(c0, ..., cn)`:

1. **Match the conclusion.**  Each argument `ai` against `ci` as a
   pattern: a case variable not yet bound is bound to `ai`; a bound one
   is compared (so `lseg(p, p, \Nil)` checks `a0 == a1`); `\null` and
   constants are compared; `\Nil` and `\Cons(x, y)` destruct the list
   value and match `x`, `y`.  Any other term (`\Cons(t, \concat(l, r))`
   in `tree`) is compared once its variables are known.
2. **Premises, as soon as their variables are known**: a known premise
   is checked (in C, below); an equation `v == t` with `v` unknown binds
   `v` (`a->next == c` in `reach`); an inductive premise `Q(...)` whose
   unknown arguments are variables first computes them with a witness
   function of `Q` (below) and is then checked.  The order is the
   source order, except that a premise waits until it can run.
3. A premise whose variables nothing determines is a diagnostic:
   deciding the case would need a search (`some_path` in
   `tests/untranslatable.c`).

This decides the least fixpoint exactly when the recursion is well
founded on the data (each recursive premise on a smaller list, or on a
node reached through the heap of a finite structure).  On a cyclic or
shared heap the recursion is cut by the step bound and gives false,
which is the least fixpoint's answer for a cycle.

### Premises and terms in C

- `\valid(p)` / `\valid_read(p)`: `rac_valid(p, sizeof *p)`, "p and its
  bytes lie in a registered, not freed, block" (the registry,
  `rac_rt.c`; plain C cannot query E-ACSL's shadow memory, and must not
  read freed memory).
- **Every read is guarded** (`p->f`, `*p`, and every index `e[i]`,
  whatever `e` is, since an index can leave its object) by `rac_valid`
  at the atom that contains it: an atom whose memory is unreadable is
  false.  Guards stay where the read is: inside the arm of `?:` that
  reads, after the left operand of `==>`, `||`, `&&` (C's
  short-circuit), so `(p == \null ? 0 : p->key) == 0` holds for
  `\null`.  When
  the spec says `\valid(p)` first (as `dll` and `lseg` do) the guard is
  redundant; when it does not, the twin is stricter than ACSL, whose
  value for an invalid read is unspecified.
- Integer arithmetic of type `integer` in `long` (overflow beyond 64
  bits is not modelled).
- Bounded integer quantifiers become loops in helper functions (`q1_k`),
  with the bounds taken from `lo <= k`, `k < hi` (or `<=`) conjuncts or
  premises.
- Predicates and logic functions a twin calls get their own C twin
  (`tw_mem`, `tw_disjoint`).
- `\initialized`, `\at` at another label, two-label definitions:
  diagnostic (not in C; they stay available in ACSL).

### Witness functions (modes)

For each inductive `P`, output position `o` and set `I` of input
positions, the generator tries to build `m_P_<o>_of_<I>`, which
computes argument `o` from the arguments at `I` by running the cases
"forwards": inputs matched as above, premises over the inputs checked,
equations and inductive premises used to bind variables (recursively,
with other modes), until the conclusion's `co` is known; then it is
the result.  A case where `co` is a variable that occurs nowhere else
returns a default ("any value works", e.g. `prev` of `dll(prev,
\null, \Nil)`).  Premises that mention computed values only (such as
`!mem(h, s)`) are not checked: the witness is only a candidate.

A mode is **exported** (as builtin `rac_P_<o>_of_<I>`, in the manifest
and for binder elimination) only when it is a function of its inputs:

- its cases are provably exclusive on the inputs (one has `x == \null`,
  `\Nil`, `a == b` where the other has `x != \null`, `\Cons`, `a != b`,
  or different constants); otherwise first-match could pick the wrong
  case (`reach`'s `b from a`, `lseg`'s `s from from`);
- every mode it uses is exported-quality and never "any value"
  (otherwise a value constrained elsewhere in the case is guessed:
  `bst`'s `lo from t, hi`).

Smallest input sets first; a superset of an exported mode is not tried.
Rejected modes are listed in the diagnostics ("not exported").  For B1:
`dll`: `s from h`, `prev from h` (any value when `h == \null`), `h from
s`, `prev from s`; for `tests/shapes.c`: `lseg`: `s from from, to`,
`to from from, s`, `from from to, s`; `tree`: `s from t`; `bst`: none.

**Member walk.**  For `P(root, node, list)` shaped like `dll` (a case
with conclusion list `\Cons(h, t)`, `h` at the node position, premise
`h != \null`, a recursive premise `P(h, ..., t)` putting `h` at the root
position, and a premise `h->F == root`; the other case concluding
`\null` and `\Nil`), the generator adds `rac_P_<node>_of_member(x)`: the
node `h` with `P(\null, h, s)` and `x` in `s`, found by walking from `x`
along `->F` to the node whose `F` is `\null` (`rac_dll_h_of_member`,
walking `ptr_to_previous`).

**Using witnesses** (in the spec block here, and in annotations by
`gen_rac.py` from the manifest): in `\exists xs; c1 && ... && cn`, each
list / pointer variable `x` gets a witness from a conjunct `P(...)`
(or a predicate defined as a conjunction containing `P` of its own
parameters, as `live_dll`): `x` at an exported mode's output with its
inputs known: the mode's function; `\Cons(e, x)` there: `rac_tail` of
it; `x` at the node position of `P(\null, x, s)` with a conjunct
`y == \nth(s, k)`: the member walk.  Witnesses are substituted (E-ACSL
33 has no `\let` on pointers); integer variables stay in an `\exists`
over the conjuncts that use them.  `\forall xs; p ==> q` over lists
likewise from the conjuncts of `p`, but only with exact witnesses (no
"any value").  `\forall` over pointers is refused.

**Why the result is exact.**  The instantiated body is always checked
in full, so a true result is a real witness.  If the existential is
true, the exported mode computes the only value the conclusion allows
(exclusive cases, determined outputs), so the instantiated body is true
too; an "any value" witness is used only where the variable occurs in
no other conjunct.  Up to the step bound.

### Step bound

Every twin and witness call spends a step and goes one level deeper
(`rac_tick`): over `RAC_FUEL` (10^6) steps or `RAC_DEPTH` (20000) levels
the computation fails (false, or no witness), so a cyclic, shared or
corrupt heap gives an answer instead of a hang or a C stack overflow.
Each builtin restarts the count.  The price: a structure deeper than
20000 is rejected (`tests/shapes_test.c` checks a 30000-node list).

### Lists

`\list<T *>` values are `struct rac_seq` (cons cells, or array slices),
passed to ACSL as `long` handles (`rac_list`; 0 is `\Nil`); "no witness"
is a distinct bad value of length 0 that no twin accepts.  Cons cells
are hash-consed, so recomputing a witness on an unchanged heap (E-ACSL
evaluates a witness term at each use, and at each index under a
quantifier) allocates nothing; without this B1 exceeded E-ACSL's 128 MB
heap limit.  A cons list gets an array on its first `\nth`, shared by
all its suffixes.  All values are freed by `rac_reset()`.

### The executable spec block

- inductive `P`: `predicate P{L}(...) = rac_P(...) != 0;`
- a predicate / function with one label or none: printed back in ACSL
  from the AST with `\list<T *>` → `rac_list`, `\length` / `\nth` /
  `\concat` / `\Cons` / `\Nil` → `rac_length` / `rac_nth` /
  `rac_concat` / `rac_cons` / `(rac_list)0`, the liveness model as the
  registry, binders over lists and pointers replaced by witnesses;
- two labels, no definition, or using a dropped definition: dropped,
  named in the diagnostics and the manifest (`gen_rac.py` then drops
  any annotation conjunct that uses it);
- lemmas and axioms: left out (proof facts).

Conjunctions are split only where the AST has `&&` (Frama-C's parser
applies ACSL precedence, so `a ==> b && c` is one implication); the
premises of a case are the conjuncts of each `==>` antecedent.
`gen_rac.py` applies the same E-ACSL 33 workarounds to this block as to
annotations (`wrap`, `null_args`; see `../bench/b1/rac/README.md`).

## Diagnostics (refusals)

`tests/untranslatable.c` / `.expected` (checked by `tests/check.sh`):

```
some_path: NOT TRANSLATED: case some_path_any: premise reach{L}(m, a) needs m, and reach has no mode computing a from b (...)
init_list: NOT TRANSLATED: \initialized{L}(h): \initialized needs E-ACSL's shadow memory, which plain C cannot query
above: NOT TRANSLATED: case above_key: conclusion argument k + 1 has variables no premise determines
two_states: NOT TRANSLATED: 2 labels: E-ACSL 33 does not execute predicates under labels
uses_some_path: NOT TRANSLATED: uses some_path (...)
pointed_to: NOT TRANSLATED: \exists node *q; \valid{L}(q) && q->next == p: no witness for q
weight: NOT TRANSLATED: declared without a definition
```

Exit status 1 when an inductive cannot be translated; a dropped
non-inductive definition only weakens the checks (exit 0, reported).

## Limits

- **Not generated**: twins for `\initialized`, two-state predicates,
  `\at` at other labels, `\separated`, `\offset`, `\base_addr` outside
  the liveness model, `\let`, sets, reals, `\match`; `\forall` over
  pointers; existentials whose variable no conjunct determines;
  overloaded logic names.  Logic functions (`logic T f(...) = t;`) get a
  C twin when a twin calls them, but no test covers that path yet.
- **Witness modes are syntactic**: exclusivity is recognised only from
  `\null` / `\Nil` / `\Cons` / equal-variable / constant patterns and
  `!=` premises on inputs; a mode the rules cannot prove exact is not
  exported, even if it is (no SMT).  The member walk is one fixed shape.
- **Twins are stricter than ACSL** where the spec reads memory it has
  not said is `\valid`, and for valid non-heap memory (stack nodes are
  not in the registry); and bounded (`RAC_FUEL`, `RAC_DEPTH`).
- **C `integer`** is `long`.
- **One list element type** gets `rac_cons`; several get
  `rac_cons_<T>` (all element types are collected before anything is
  printed), but `gen_rac.py`'s `rac_null` and `rac_nth`'s result type
  handle one node type.
- **The twins are not proved** against their predicates.  The contract
  `ensures \result != 0 <==> P(...)` (plan §4 item 5) is not generated:
  the twins work on `struct rac_seq` and the registry, so WP would need
  an abstraction from `rac_seq` to `\list`, and a registry invariant
  that implies `\valid`; a project of its own.

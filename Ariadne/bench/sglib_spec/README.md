# Spec templates for sglib (plan Q12)

sglib is generic through macros: `SGLIB_DEFINE_DL_LIST_FUNCTIONS(type,
comparator, previous, next)` expands to the list functions for one node
type and two link fields.  `sglib_dl_list_spec.h` does the same for B1's
ACSL: its macros take the same parameters and expand to the predicates,
the public contracts and the proof annotations.  Each instantiation is
still expanded and proved on its own; the template only removes the
need to rewrite the spec by hand for a new one.

## Does Frama-C expand macros inside annotations?

Yes, in every position B1 needs.  Frama-C 33 preprocesses annotations
(`-pp-annot`, on by default with gcc's cpp), so a macro used inside
`/*@ ... */` is expanded before the ACSL is parsed (the liveness model's
`/*@ ARIADNE_ALLOC */` already relied on this).  Checked on a probe file
and then on B1:

| Position | Works | Note |
|----------|-------|------|
| file-scope logic block (predicates, inductive, lemmas) | yes | several declarations per macro |
| function contract | yes | |
| assert inside a function body | yes | **one assert per comment**: a macro that expands to two asserts in one comment is refused ("Only one code annotation is allowed per comment"), so each assert is its own macro |
| loop annotation (invariants + `loop assigns`) | yes | one macro for the whole loop annotation |

The functions are generated by sglib's macros, and a macro cannot put a
comment (an annotation) into the code it generates.  So, as before (plan
Q4), the annotated file holds sglib's *expanded* code (`gen.sh`), and the
annotations in it are template invocations, written next to the code
they annotate.  WP and RTE place the expanded clauses at the line of the
invocation.

## Instantiating

```c
#include "ariadne_alloc.h"
#include "sglib_dl_list_spec.h"      /* -I/ariadne/bench/sglib_spec */

/*@ // the fields the comparator reads (template parameter cmp_reads)
    predicate dllist_cmp_reads{L}(dllist *p) = \initialized(&p->i);
    SGLIB_DL_LIST_SPEC(dllist, ptr_to_previous, ptr_to_next,
                       dllist_cmp_reads)
    SGLIB_DL_LIST_LEMMAS(dllist, ptr_to_previous, ptr_to_next) */

/*@ SGLIB_DL_LIST_CONTRACT_ADD(dllist, ptr_to_previous, ptr_to_next) */
void sglib_dllist_add(dllist **list, dllist *elem) { ...
    /*@ SGLIB_DL_LIST_ANNOT_ADD_LINKS(dllist, ptr_to_previous, ptr_to_next) */
```

`../b1/b1.c` is the full instantiation (B1: `dllist`, `ptr_to_previous`,
`ptr_to_next`); `../b1/b1_frozen.c` uses only the public macros;
`../selftest/selftest_dl.c` instantiates the public macros at the
self-test's `DoubleLinkedList`, `previous`, `next`, `st_cmp_reads`.

| Macro | What | Public (Q11)? |
|-------|------|---------------|
| `SGLIB_DL_LIST_SPEC(type, previous, next, cmp_reads)` | predicates `live`, `mem`, `all_live`, `all_init` (links only), `dll`, `unchanged`, `all_cmp_reads`, `live_dll`, `in_live_list`, `in_cmp_list`, `heap_node`, `iter_at`, `iter_fields`, `iter_pre`, `iter_ok` | yes |
| `SGLIB_DL_LIST_CONTRACT_{ADD, GET_FIRST, GET_LAST, IT_INIT}(type, previous, next)`, `..._IT_INIT_ON_EQUAL(type, previous, next, cmp_reads, cmps)`, `..._IT_NEXT(type, previous, next, cmps)` | the contracts of the six verified sglib functions (B1's driver `b1` has its own) | yes |
| `SGLIB_DL_LIST_CONTRACT_COMPARATOR(type, cmp_reads, a, b)` | the contract every comparator meets | yes |
| `SGLIB_DL_LIST_LEMMAS` | the fifteen lemmas | no |
| `SGLIB_DL_LIST_ANNOT_*` | the asserts and loop annotations inside those functions | no |

### The parameters

- sglib's own: `type`, `previous`, `next`.  The comparator itself is not
  a parameter of the list macros: none of the verified functions calls
  it.
- **`cmp_reads`** (owner's decision, 2026-11-05): a client predicate
  naming the fields the comparators read; `all_cmp_reads(s)` lifts it to
  a list, for the functions that compare nodes.
- No payload parameter: `all_init` covers the links only (owner's
  decision, 2026-11-05), and a client that reads its payload tracks its
  initialisation itself (B1's driver: `payload_init`).
- **Names.**  Predicate and lemma names do not depend on the
  parameters, so one translation unit holds one instantiation.  The
  iterator type is `struct sglib_<type>_iterator`, built with `##` as
  sglib does.

### The comparator rule

Every comparator, a function or a macro inlined at its call sites, must
be proved free of runtime errors (WP with `-wp-rte`) under
`SGLIB_DL_LIST_CONTRACT_COMPARATOR`: both arguments `\valid_read`, their
`cmp_reads` fields initialised, `assigns \nothing`, and both blocks not
freed (`!dead`, which every read needs under the `-ariadne` liveness
model; a stack or global object is never dead).  For a macro the
obligations are the RTE goals at each call site.

- The self-test's `myListCmp` (a function): 7/7 goals proved under the
  contract (`../selftest/cmp_wp.sh`; Qed 3, Alt-Ergo 3, CVC5 1).  Its
  `e1->n - e2->n` is `unsigned`, so it cannot overflow; converting the
  difference to `int` is implementation-defined, not undefined, and RTE
  checks it only with `-warn-signed-downcast` (then
  `typed_myListCmp_assert_rte_signed_downcast` stays open).
- B1's `DLLIST_COMPARATOR` (a macro): its original subtraction
  overflowed; fixed as bug fix #1 (`../b1/CHANGES.md`), after which
  WP's simplifier proves its overflow goals at every call site.

### Subcomparator (owner's decision 3, 2026-11-05; option B)

**The `calls` check.**  `calls_probe/run.sh` (WP with Alt-Ergo, Z3,
CVC5, `-wp-rte`): WP 33 proves an indirect call that is a statement and
carries `calls` (the call-point goal, and each listed function's
precondition at the call; a call missing a precondition stays open,
`typed_bad_call_cmp1_requires`), but cannot attach `calls` to a call in
a `while` condition, sglib's shape (`Missing 'calls' for default
behavior`; the goals after the call stay open).  A call in an `if`
condition (`if (f(x, y) == 0) break;`) works like a statement.

**The refactor.**  So, by the owner's option B, B1's instantiation
rewrites `it_next`'s two loops as `while (ce != NULL) { if (scp(eq, ce)
== 0) break; ce = ce->previous; }` (and forward with `scp(ce, eq)`),
logged as change #2, a *verification refactor*, in `../b1/CHANGES.md`
(plan Q11); the vendored sglib is unmodified.

**The contracts.**  `it_init_on_equal` and `it_next` take `cmps`, the
comparators a client may pass, written `(n, f1, ..., fn)` with n from 0
to 4 (B1: `(0)`; the self-test: `(1, myListCmp)`; the length is explicit
because Frama-C preprocesses annotations as C11, where an empty macro
argument cannot be detected).  `it_init_on_equal` requires
`subcomparator` to be `\null` or one of them and, with one,
`\valid_read(equalto)`, `!dead` of its block and `cmp_reads(equalto)`,
and `in_cmp_list(list)` (every node of the whole list has its
`cmp_reads` fields initialised); it ensures `it->subcomparator ==
subcomparator`.  `it_next` requires membership again and keeps
`subcomparator`.  `iter_fields` records the `equalto` facts and
`iter_at` `all_cmp_reads(s)` when a subcomparator is set.  Private:
`SGLIB_DL_LIST_ANNOT_IT_NEXT_CALLS(cmps)` puts `calls f1, ..., fn;`
before each indirect call (for `(0)`, an `assert \true;`: the calls are
unreachable), with loop annotations for the two search loops and the
asserts `mid_back`, `mid_fwd`, `found`, `ce_live`, `cmp_frame`,
`eq_frame`, `start_cmp`.

**Where it is proved.**  B1 passes no comparator, so its `it_next` has
the calls but cannot reach them.  `../selftest/wp/` (`gen_wp.py`)
instantiates B1's annotated functions at the self-test's
`DoubleLinkedList`, `previous`, `next`, `st_cmp_reads`, `(1,
myListCmp)`, on sglib's own expansion (with the refactor; the renamed
code is checked equal to it token for token), plus a driver that
iterates with `myListCmp`.  WP proves both indirect calls there:
`typed_sglib_DoubleLinkedList_it_next_call_point_myListCmp_s689` and
`..._s712_part{1,2}` (the pointer is `myListCmp`), and myListCmp's
preconditions at both calls
(`typed_sglib_DoubleLinkedList_it_next_call_myListCmp_requires{,_2}`,
`..._call_myListCmp_2_requires{,_2}_part{1,2}`).

## Textual tools see Frama-C's expansion

The guardrails (spec hashes, ACSL and ghost lints) and the RAC pipeline
read annotations as text.  They run on the source with each annotation
replaced by Frama-C's own expansion of it
(`../../harness/acsl_expand.py`): `frama-c -keep-temp-files` on the
source keeps the output of Frama-C's annotation preprocessing
(`cppannot*.c`), which holds every *active* annotation expanded with
the macro state Frama-C had there (its C preprocessing resolves `#if`,
`#ifdef`, system headers and pragmas first).  Each expanded annotation
is one line, padded with the original's newlines, so line numbers do
not move; an annotation Frama-C never reads (in `#if 0`, or the `#else`
of a true `#if`) is removed.  So the frozen-spec hashes cover exactly
the ACSL that Frama-C reads, not the invocation text.

Defence in depth (guardrail `directives`): an edited source must have
exactly the baseline's preprocessor directives, in order; an added,
removed or changed `#define`, `#if` or `#pragma`, anywhere in the code,
fails.  No pipeline step adds directives (the annotator writes
annotations only; bug fixes and verification refactors change the
benchmark itself).  The harness also hashes this directory and
`plugin/share` before and after a run (`benchmark_untouched`).

(An earlier expander forwarded only `#define`, `#undef` and `#include
"..."` lines to cpp, so a `#define` in a false `#if` branch, a macro of a
system header or a `push_macro` could make the hashed spec differ from
what Frama-C reads; Codex's review of PR #234 found it.)

## B1 from the template

The expansion is token for token the ACSL of the hand-written b1.c
(commit 3ba8421c and before): every predicate, contract, lemma and
in-body annotation has the same comment-free, whitespace-normalised
text (`guardrails.spec_items` and the in-body annotation list compared).
WP produced the same 321 goals with the same names, and its cache
reused the SMT results.  The owner's decisions of 2026-11-05 then
changed the spec; `../b1/README.md` has the current numbers.
